# Analytics 时间范围扩展设计

## 目标

在数据分析看板中添加"最近 14 天"和"全部数据"两个时间范围选项，让用户可以更灵活地查看不同时间段的数据分析。

## 当前状态

- 已有时间范围：最近 7 天、最近 30 天
- 状态管理：`const [days, setDays] = useState(7)`
- 筛选器位置：页面 Header 下方，核心指标卡上方

## 设计方案

### 新增时间范围

| 选项 | days 值 | 说明 |
|------|--------|------|
| 最近 7 天 | 7 | 已有 |
| 最近 14 天 | 14 | 新增 |
| 最近 30 天 | 30 | 已有 |
| 全部数据 | null | 新增，表示不限制天数 |

### UI 布局

按时间顺序排列 4 个按钮：
```
[最近 7 天] [最近 14 天] [最近 30 天] [全部数据]
```

### 样式规范

- 保持现有按钮样式
- 选中状态：`bg-blue-600`
- 未选中状态：`bg-gray-700 hover:bg-gray-600`
- 响应式：在小屏幕上可能需要换行或滚动

## 技术实现

### 修改文件

1. `src/pages/Analytics.jsx` - 添加新按钮和状态处理
2. `src/utils/analytics.js` - 确保工具函数能处理 `null` 值（全部数据）

### 关键改动

#### Analytics.jsx
```jsx
// 状态初始化（保持 7 天为默认）
const [days, setDays] = useState(7);

// 添加两个新按钮
<button onClick={() => setDays(14)} className={...}>
  最近 14 天
</button>
<button onClick={() => setDays(null)} className={...}>
  全部数据
</button>
```

#### analytics.js 工具函数
需要检查所有 `calculate*` 函数，确保当 `days` 为 `null` 时能正确处理（不过滤日期，使用全部数据）。

### 边界情况处理

1. **空数据**：当 `days=null` 且无任何日志时，保持现有空状态 UI
2. **数据量过大**：如果用户有数年数据，图表渲染性能需要关注（暂不优化，等发现问题再说）
3. **跨日计算**：健康度、趋势分析等函数需要正确处理无限时间范围

## 验收标准

1. 4 个时间范围按钮正确显示
2. 点击每个按钮能正确切换时间范围
3. 所有图表和指标能正确响应时间范围变化
4. "全部数据"选项显示所有历史数据
5. 选中状态视觉反馈正确
6. 构建无错误，运行无警告
